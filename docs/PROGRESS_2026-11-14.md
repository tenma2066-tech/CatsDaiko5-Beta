## 今回までに追加・強化した内容

### Cloud Run / Firestore実行基盤
- SQLite + optional GitHub snapshotの既存方式を `legacy` として維持。Firestoreは明示選択時のみ使い、暗黙fallbackしない。
- 注文・決済Repository、Firestore transaction、決済attempt digest一意性、credential保存とexecution outbox登録の原子性。
- Cloud Tasks transactional outbox publisher、OIDC Dispatcher、Cloud Run Job launcher/Worker、Firestore progress/result、worker slot、transfer-code lock。
- outbox再登録、Job終了reconcile、曖昧起動のread-only inspection。
- Dispatcherが保存した完全なCloud Run Execution resource nameをworker owner tokenで上書きしない。Firestore Emulator回帰テストで保持を確認。
- Dispatcher payloadのorder IDを、immutable outbox上のorder IDと照合してからslot予約する。誤った組み合わせはJob起動前に拒否する。

### PayPay / 移行安全性
- 旧PayPay ledger確認を通常のread/write SQLite contextから分離し、`read_blob_readonly` で暗号化snapshotを読み取り専用で取得する。
- ledger snapshot欠落・復号失敗・schema不正の場合はfail-closed。Firestore決済側の `runtime_store` エラーは `review` に固定し、自動再受付しない。
- Migration dry-runで注文snapshotとPayPay ledger snapshot両方のschema状態を表示し、いずれかがFAILEDならapply拒否。
- paid/fulfilling/completed注文のdigest欠落、digest-to-order不一致、paid state不一致、invalid/orphaned/duplicate attemptsを検査。すべて0でなければapply拒否。
- 注文・ledger行の型/範囲（注文ID、hash、暗号化blob、金額、数量、timestamp、attempt state等）を検証し、不正行があれば部分import拒否。
- Firestoreへのcreate-only importで、`legacy_imported=true` の同一移行docのみを再実行時skip。同じID/digestの別用途docや別注文のattemptが存在すれば衝突として停止。
- これらの検査・衝突動作はunit testsおよびFirestore Emulator integration testsに追加済み。
