# Beta（Fly.io + PayPay決済）引き継ぎメモ

最終更新: 2026-11-15（料金改定まで反映） / ブランチ: `main`（2026-11-20 に `claude/zealous-ritchie-5o2epn` から移行）（Beta リポジトリ）

## 1. 目的と全体像
- CatsDaiko5（安定版）の内容をベースに、Beta は **ログインを廃止し、PayPay決済が確認できてから実行**する個人利用版。
- 公開URL: https://catsdaiko5-beta.fly.dev/ （管理画面は `/admin`）
- 実行環境: Fly.io（東京 `nrt`、1台、メモリ1GB、常時起動）。Renderは使わない。

30. 実行が永久に止まる不具合（2026-11-17 本番で発生）: bcsfe のセーブ送信（S3へのアップロード）が待ち時間の上限なしで、TLSハンドシェイクで止まると終わらなかった。実行用プロセスで requests に上限（接続20秒・応答120秒）を付け、接続の段階（ハンドシェイク含む・何も送っていない）の失敗だけ最大3回やり直す。送った後の失敗は従来どおり「結果不明」で自動再試行しない。デプロイは処理中なら入れ替えずに中止（手動実行時のみ `allow_running` で止まった件数を許可）。調査用に `vps-diag.yml`（状態・ログ・実行中プロセスのスタック）。
31. 根本原因（2026-11-17）: VPS（XServer）のネットワークの MTU が 1442 なのに Docker のネットワークが 1500 で、ゲームのセーブ送信先（AWS S3）との TLS 接続で大きなパケットが捨てられ、接続が詰まっていた（移行直後の1件目は偶然通った）。`deploy/vps/docker-compose.yml` でネットワークの MTU を 1400 に。初回だけネットワークを作り直す。接続段階で3回失敗した場合は「結果不明」にせず、支払い済みに戻して再実行できるようにした。

## 3. 動作の流れ（顧客側）
1. 項目を選び「決済して実行」→ `POST /run` は**実行せず注文を作る**（金額はサーバーが計算）。
2. 支払いモーダルに金額・内訳が出る → PayPayで表示金額ちょうどの送金リンク（パスコードなし）を貼る。
3. `POST /api/orders/<id>/pay` → リンク検証（金額・期限・未受取など）→ 受け取り → ジョブ開始。
4. 状態: `unpaid → paying → paid → started`。保留/結果不明は `hold`、復帰不能は `dead`。
5. `hold` のとき: 送金者がPayPayアプリで保留を解除 → 画面が20秒ごとに自動確認（「今すぐ確認する」でも可）→ リンクが PENDING なら金額等を再検証して同じリンクをもう一度受け取り、COMPLETED なら支払い済み → 自動で開始。新しいリンクは受け付けない。
6. 支払い済みで待機枠が満杯（429）の場合は、再送金なしでボタンを押し直せば開始できる。

## 4. 料金（`app.py` の `PRICES` / `compute_amount`）
| 内容 | 料金 |
|---|---|
| キャラ指定（1体ごとに、レベル・形態・本能を1項目ずつ。設定なしの解放のみは1件） | 50円/項目 |

## 7. 既知の注意点・未対応
- **保留まわりは本物のPayPayでは未検証**（偽のPayPayでのテストのみ）。前提: 受け取り済みは `SUCCESS`、解除後は `PENDING` のまま再受け取り可（zip元コードの実運用ロジックと同じ）、PENDING時の `receiver.externalId` は自分のID。前提が外れた場合は管理画面の「未完了の注文」の表示（最後の結果／PayPay:）で分かり、「支払い済みにする」で救済できる。
- PayPayの非公式Web APIを使用。仕様変更で動かなくなる可能性。保留の実機での復帰フロー（`confirm_received`）は、テストはあるが本物のPayPayではまだ未検証。
- PayPayリンクの状態名（CANCELED/EXPIRED 等）への対応づけは推測を含む。想定外の表示があれば要調整。
- 台数は1・ワーカーも1のまま（ボリューム専用・メモリ上のジョブ管理のため）。
- **Fly.io のトライアル終了後はカード登録が必要**（目安: 月5〜8ドル）。カードがない場合の案: バーチャルのプリペイドカード（Kyash等）でFlyを継続／日本のVPS（ConoHa等）へ移行（GitHub Actions経由のSSHデプロイで対応可能）。未決定。
- 以前この環境に保存した `api.fly.io` のトークンは使えていない。Fly側で失効させておくこと。
- zip に含まれていた Discord トークン等は使っていない。他人に渡した可能性があれば再発行。
- UI/UXは引き続き調整予定（ユーザー希望）。
- 安全モードの初期値はオフ（猫缶・レアチケ・プラチケ・プラチナのかけら・レジェチケも実行される。BANの恐れは利用者の自己責任）。オンにすると外され、料金にも含まれない。
