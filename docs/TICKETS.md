# チケット購入・支援BOX・ソースコード購入

トップの4枚目「チケット購入🎫」（`/ticket`）と5枚目「支援BOX」（`/support`）。
代行ではなく「クーポンコードを買う」商品。支払いは代行と同じ PayPay 送金リンクの流れ（保留・自動再確認・注文番号での呼び戻しもそのまま使える）。

## 商品とコード

| 商品 | 料金（`PRICES`・管理画面で変更可） | 発行されるコード | 効果 |
|---|---|---|---|
| 1回なんでも無料チケット | `ticket_once` 1000円 | `FR-` 種類 `free` | 1回の注文が金額に関係なく0円。180日有効（`TICKET_ONCE_DAYS`） |
| 期間無料チケット | 1〜30日：`ticket_day` × 日数^0.7（10円単位切り上げ）／無制限：`ticket_unlimited` 9800円 | `PS-` 種類 `period` | 期間中は何度でも0円。1件ずつ順番に（進行中の注文があると `coupon_busy`） |
| 支援BOX | 100〜100,000円（`SUPPORT_MIN`/`SUPPORT_MAX`） | `SP-` 種類 `pct30` | 30%引き・金額の下限なし・90日・1回 |

期間料金の例（初期値）：1日 500円／7日 1,960円／14日 3,180円／30日 5,410円（1日あたり約180円）／無制限 9,800円。
30日の料金が無制限を超える設定にしても、`ticket_period_price` が無制限の料金で頭打ちにする。

## 仕組み

- 注文：`POST /api/ticket/order {plan: once|period, days}`・`POST /api/support/order {amount}` → 注文に `product` を持たせる（`job` は無い）。クーポン欄は受け付けない。メンテ中は作れない。
- 入金確認後：`_start_paid_order` → `_deliver_product` がコードを発行して `done`（`result` にコード・期限）。同じ注文からは同じコード（`coupon_issue_kind` が発行元の注文で重複を防ぐ）。発行に失敗したら `paid` に戻し、再送金なしで押し直せる。管理画面の「支払い済みにする」でも発行される。
- 使う側：`_place_order` が種類で分岐。`period` は押さえ（reserve）も使用済み（consume）もしない代わりに、同じコードの進行中の注文があれば 409。開始に失敗した同じ人の0円注文は、次の注文で自動的に閉じる（チケットが詰まらない）。
- 期間は発行（入金確認）時から。無制限は100年（`UNLIMITED_DAYS`）。
- 画面：コードは `/api/orders/mine` の完了注文（3日）と、端末の `localStorage`（`tn-codes`）の両方から表示。注文番号で呼び戻すと再表示できる。
- 比較グラフ（`/ticket`）：1日に頼む回数 × 1回の金額（初期値＝いまの料金表の単品の中央値）で、毎回払う累計とチケット代を SVG で描く。元が取れる日に印、損な使い方のときは正直に「毎回払うほうが安い」と出す。

## ソースコード購入（`/source`・6枚目）

このお店の仕組み一式を zip で売る。料金は `PRICES["source_code"]`（初期値 5000円・管理画面で変更可）。

- 注文：`POST /api/source/order` → `product: {type: "source"}` の注文。支払いはほかと同じ PayPay 送金リンク（保留・呼び戻しも同じ）。クーポン・チケットは使えない。
- 入金確認後：`_deliver_product` が「ダウンロードの権利」を渡して `done`（クーポンは発行しない）。注文は **30日**残す（`SOURCE_KEEP_DAYS`・注文の `keep`）。
- ダウンロード：`GET /api/source/download/<注文番号>`。本人（または注文番号で呼び戻した人）で、完了したソースコードの注文だけ。
- zip は `source_pack.py` が、いま動いているコードから作る（変更があったときだけ作り直す）。
  - 入れるものは許可リスト（`INCLUDE`）。`instance/`・台帳・ログ・`.env`・`xbot/`・`exchange/`・`CLAUDE.md`・`AGENTS.md`・サーバーの鍵の指紋は入らない。
  - 店名・問い合わせ先・ドメイン・検索の所有確認・レビュー用ポストは `REPLACE` で置き換える（`site_config.py` の既定値は空になる）。
  - 店名や連絡先が**描き込まれた画像**（`static/flow.*`・`tsum-flow.*`・`ogp-nyanko.jpg`・`ogp-tsum.jpg`）は入れない。無くても画面は成り立つ。
  - 置き換え後に持ち主の情報（`FORBIDDEN`）が残っていたら、zip を作らずエラーにする。**新しく持ち主の情報をコードに書いたら、`REPLACE` と `FORBIDDEN` に足すこと。**
  - 買った人向けの `LICENSE.md`（再配布不可・無保証）と `docs/SETUP.md`（導入ガイド）が入る。
- 確かめ方：`python source_pack.py out.zip` で手元に作れる。`test_source.py` が中身（必要なものが入り、持ち主の情報が無いこと）と購入〜ダウンロードを確かめる。

## 実績（`/reviews`・7つ目。トップのいちばん上の細長い帯）

完了した代行の注文に、お客さんが **星1〜5と感想（20〜400文字）** を書ける。以前の「X のポストにリプライ」を置き換えたもの。

- **全部門で必須・サーバーが守る**：完了した注文の結果（引継ぎコード・引き継ぎ番号・アカウント情報）は、評価を受け取るまで
  サーバーが返さない（`_review_locked`。`/status` は `result_locked`、`/api/orders/mine` は `locked` で結果は `null`）。
  画面で隠しているのではないので、開発者ツールでも先には読めない。画面は入力欄（全画面共通の `static/review.js`）を出し、
  送信できたら結果を取り直す（にゃんこ：`rvOpen`、ツムツム・ぷにぷに：`static/shop.js` の `requireReview` / `reviewThenShow`）。
- 対象は、ふつうに完了した代行の注文（`gate`）。途中で止まったが結果が出た注文（引き継ぎ後の失敗など）・管理者の無料実行・
  チケット等は対象外。保存の不調が2回続いたら、その注文は免除して結果を渡す（`review_waived`）。言葉の検査で断ったときは免除しない。
- **汚い言葉・宣伝は保存しない**：`review_filter.py` の `check`。暴言・侮辱・差別語・性的な言葉（`JA_WORDS`・`EN_WORDS`）と、
  URL・@ID・連絡先・電話番号を 400 で断る（幅・大小をそろえ、あいだの空白や記号を取り除いて探す）。
  普通の言葉を巻き込む語は登録しない（「ばかり」「カスタム」「やくそく」「イエロー」など。`test_reviews.py` の `FINE` に例）。
  低い評価や不満そのものは止めない。お店ごとに足す言葉は、管理画面「実績」タブ →「実績に載せない言葉」（`review_words.json`）。
- 保存：`POST /api/reviews {stars, text, order?, job?}`。本人の・完了した・代行の注文で、まだ書いていないものだけ（1注文1件。注文に `reviewed` の印）。対象が無いときも `ok`（`saved:false`）を返し、画面は先へ進める。
- **お客さんを止めない**：保存に2回続けて失敗したら、入力欄は閉じてコードを見せる。
- 置き場所：台帳（SQLite）の `reviews` 表（`paypay_gateway.review_*`）。注文番号は外へ出さない。部門名と日付だけ添える（注文内容・名前は出さない）。
- 公開：`/reviews`（平均・星ごとの件数・一覧・「もっと見る」＝`GET /api/reviews?before=id`）。`REVIEW_POST_ID` があれば「今までの実績を見る（X）」のリンクを出す。
- 管理：`/admin` の「実績」タブで非表示／再表示（平均と件数からも外れる）。
- 止める：`REVIEWS_ENABLED=0`（入力のお願い・ページ・トップの帯・sitemap すべて消える）。
- テスト：`test_reviews.py`（保存・検査・公開・管理）、ブラウザは `test_ui_results.py` の `ReviewGate`。
