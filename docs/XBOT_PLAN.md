# xbot 高性能化の計画（ブランチ `claude/xbot-next`）

本番（`main`）には入れていない。`xbot-deploy.yml` は `main` でしか動かないので、このブランチに push しても VPS は変わらない。

## ゴール
1. **予約投稿が DM のせいで遅れない・止まらない**
2. **DM の失敗が続いても暴走しない**（以前、一晩タイムアウトを繰り返して投稿まで止めた）
3. **全部の DM に、何かしら適切に応える**（自動で答えてはいけないものは人に回す）
4. **ふつうの会話にも返信できる**（いまは未解決）

## フェーズ1：作って、テスト済み（このブランチ）
| 内容 | 中身 | 場所 |
|---|---|---|
| 投稿を優先 | DM 確認の会話の区切りごとに「予約投稿の時刻が来たか」を見て、来ていたら切り上げて先に投稿。投稿のあと5秒で続きを再開 | `worker._checkpoint`, `_auto_dm` |
| 失敗時の自動ブレーキ | DM の確認が失敗したら、次の確認までの間隔を倍々にのばす（5分→10分→20分…最大3時間）。成功したら元に戻す。管理サイトに警告を出す | `logic.dm_next_delay`, `_auto_dm` |
| 開けない会話で粘らない | 会話を開けないのが2回続いたら、その回は打ち切り（残り全件でタイムアウトを待たない） | `OPEN_FAIL_STOP` |
| 1回の長さの上限 | 1回の DM 確認は最大10分 | `DM_RUN_MAX_SEC` |
| 要対応ルール | 条件「要対応」：キーワード（例：返金・詐欺・届かない）に当てはまったら返信せず、管理サイトの「要対応」一覧に出す。返信文を入れればそれだけ送る（例：「担当者が確認します」）。「対応済み」ボタンで消える | `logic.KINDS`, `handoffs` 表, `/handoff/<id>/done` |
| 名前の差し込み | 返信文の `{name}` を相手の名前に | `logic.render_reply` |
| 受け皿の返信 | 新機能ではなく使い方：「すべてのDMに返す」を優先度 999 にすると「どれにも当てはまらないとき」の返信になる（管理サイトに説明を追加） | `page.html` |
| 計測 | 1回の DM 確認にかかった秒数を管理サイトに表示 | `last_dm_secs` |

テスト：`python3 xbot/test_logic.py`（27件、うち新規6件）。

## フェーズ2：ふつうの会話を開けるようにする実験（2026-11-22 実施・原因判明）
依頼主の OK をもらって、VPS で読むだけの実験を2回動かした（Actions の `lab`）。

| 開き方 | 結果 |
|---|---|
| M0 いまのやり方（毎回一覧を開き直してクリック） | 3件とも開けた（各1.3秒） |
| M1 ブラウザの「戻る」 | 3件とも開けた |
| M2 横の一覧から続けてクリック | 3件とも開けた |
| M3 会話ごとにブラウザを起動し直す | 3件とも開けた（遅い） |
| **M4 本番と同じ順（先にリクエスト画面→同じブラウザで会話）** | **一覧が0件** |
| M5 リクエスト画面のあと、ブラウザを起動し直して M0 | 3件とも開けた |

**原因**：本番はリクエスト画面を先に開いてから、同じブラウザで会話の一覧を見ていた。リクエスト画面を開いたブラウザでは一覧が0件になる（以前の probe の「分かったこと1」と同じ）。会話を開けない問題は、いまは起きていない。

**直し方（このブランチに実装・テスト済み）**：ふつうの会話 → リクエスト の順にし、それぞれ別のブラウザで開く（`worker._dm_body`）。

以下は実験の仕組みのメモ。

- 中身：`xbot/lab/dm_lab.py`（読むだけ。送信しない）と `xbot/lab/lab.sh`
- 本番の常駐とは別のプロセスで、**プロフィールの写し**を使う。終わったら写しは消す
- 影響：開いた会話（最大3件×4通り）は X 上で**既読**になる。それ以外は何も変わらない
- 試す開き方（M0＝いま、M1＝ブラウザの「戻る」、M2＝横の一覧から続けてクリック、M3＝会話ごとにブラウザを起動し直す）
- 出力は「成否・秒数・メッセージ数」だけ（名前・本文・ID は出さない）
- 動かすには `xbot-deploy.yml` に `lab` の手順を足して `main` に入れる必要がある（ワークフローだけの変更で、常駐は再起動しない）

結果で一番安定した開き方を、`worker._dm_body` に組み込む。
