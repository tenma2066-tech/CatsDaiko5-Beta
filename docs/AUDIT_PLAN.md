## 1. 進め方の決まり（止めない・壊さない）

1. **最初にバックアップ**（§3 P0-1）。直す前に、注文・台帳・設定・暗号鍵を戻せる状態にする。
2. **1つの直しを1つのコミットに**。まとめて大きく変えない。どのコミットでも動く状態を保つ。
3. **先にテスト**。直す前に「今の問題が出る」テストを書き、直したあと通ることを確かめる（今回のコード取り違えと同じやり方）。
4. **本番の入れ替えは今の仕組みのまま**：`main` に push すると、実行中・決済中の注文が終わるのを待ってから入れ替わる（`vps-deploy.yml`）。利用者は弾かれない。
5. **戻し方を決めておく**：おかしければ `git revert` して `main` に push すると、同じ仕組みで元に戻る。データの形を変える変更は、古い形も読めるようにしてから入れる。
6. 大きな作り直し（§2-C）は別ブランチで進め、画面の金額とサーバーの金額が一致するテストを通してから、少しずつ `main` に入れる。

## 4. 依頼主に残っている操作

1. **SSH 鍵（S2 の残り）**：XServer の VPS のコンソールで鍵を作り、秘密鍵を GitHub の Secrets（`VPS_SSH_KEY`）に**自分で貼る**（チャットには貼らない）。全部のワークフローが鍵で入れるのを確かめてから、VPS のパスワードログインを止める。
2. **暗号鍵の控え（S5 の残り）**：VPS の `/opt/catsdaiko/.env`（注文を読むための鍵）を、VPS の外（パスワード管理アプリなど）にも控える。VPS ごと失うと、バックアップの注文が読めなくなるため。
3. **パスワードの確認（S9 の残り）**：消した `auth/passwords.json` のパスワードを、ほかの場所で使っていないか。使っていれば変える。
