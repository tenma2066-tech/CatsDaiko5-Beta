# にゃんこ代行 Web版（個人用）

ブラウザから使える版です。課金・PayPay・Discordは入っていません。

## ファイル
- app.py … Webページ本体
- engine.py … 元のmain.pyから取り出した書き換え処理
- template_save.sav … 「引継ぎコード空欄」で使う初期垢の土台
- requirements.txt / render.yaml … Render用の設定

## 手順（iPhoneのブラウザだけでOK）
1. zipを「ファイル」アプリで展開する
2. GitHubで新しいリポジトリを作る（**Private**にする）

4. Renderにログイン → New → **Blueprint** → そのリポジトリを選ぶ
5. `APP_PASSWORD` と `ADMIN_PASSWORD` をRenderに設定 → Apply

- Environment: `APP_PASSWORD`（自分で決める）、`TZ=Asia/Tokyo`、`PYTHON_VERSION=3.12.8`

## 使い方
- パスワードでログイン → 「入力」タブで引継ぎコードと暗証番号を入れる
- 「アイテム」「サブ」「その他」タブで項目を選ぶ（タブの数字は選んだ件数）
- 「数量指定」タブでは、アイテムごとに個数を入力できる
  - 空欄の項目は変更しない／「最大」で上限値が入る／上限を超えると赤くなり実行できない
  - 「アイテム」タブで同じ項目をMAX選択していても、数量指定のほうを優先する
  - 次の項目は、折りたたみ欄を開くと種類ごとに個数を指定できる（名前はゲーム内の正式名）。種類ごとの指定は、同じ項目全体の指定より優先する
    - キャッツアイ（6種）・マタタビ／獣石（29種）・バトルアイテム（6種）・ネコビタン（3種）・城素材（16種）・地底メダル（4種）
    - イベチケ&福チケ（イベチケ／福引チケットを別々に）
    - 本能玉（62種×D〜Sの5等級）。「まとめて入力」で等級ごとに全種類へ一括入力でき、効果や属性で絞り込める
  - 「本能玉」は、本能玉を1つも持っていないアカウント（初期アカウントなど）でも全310種を付与する
  - プラチナのかけら・1億DL記念チケットも指定できる（1億DL記念チケットは、ゲーム内でイベント開催中のみ表示・使用できる）
- 「キャラ管理」タブの個別設定では、形態を第1〜第4形態から選べる（第4形態はそのキャラに第4形態がある場合のみ）
- 「その他」タブには、ユーザーランク報酬全受け取り・チュートリアルクリア・ガマトトのクラッシュ修正・オトート砲台のクラッシュ修正もある
  - 「オトート砲台のクラッシュ修正」は砲台データを初期化する。「施設全強化」と同時に選ぶと、修正のあとに強化する
- 「入力」タブの「よく使う組み合わせ」で、選んだ項目・数量・キャラ設定・実行モードを名前を付けて保存・呼び出しできる（保存先はブラウザ。引継ぎコードは保存しない）
- 「発行したコードをこの端末に残す」がオンなら、発行された引継ぎコードと暗証番号をブラウザに最大10件保存し、「状況」タブでいつでも確認・コピー・削除できる（共用端末ではオフにする）
- 「キャラ解放」タブでは、にゃんこDBのキャラ番号を入れて、そのキャラだけを解放できる
  - 入力例：`1, 5, 100-120`（カンマ・スペース・改行で区切り、ハイフンで範囲指定）
  - 番号はDBの表記（1始まり）で入力する。内部ではIDを1引いて処理する
  - すでに持っているキャラは変更しない。図鑑に無い番号・エラーキャラになる番号は自動で除外し、「状況」タブに注意として表示する
- 下の「実行」を押すと「状況」タブに切り替わり、進み具合が見える
- 両方空欄なら初期アカウントから作る

## v1.13: 結果の分離・通信診断・キャラ更新

- 結果の閲覧・保存と待機処理の取消は、実行したログインセッションだけが利用できます。同じパスワードや同じIPでも別ブラウザのセッションからはアクセスできません。同じブラウザのタブは共有します。ログアウト・再ログイン後は以前の結果にアクセスできないため、先に結果を保存してください。
- BCSFE通信エラーログは、既知のエラー種別とHTTPステータスのみ記録し、URL・ヘッダー・本文を出力しません。過去のログを消去する変更ではありません。

- 「キャラ解放」の「最新キャラに対応」は、配布元にある最新の日本版データを確認し、要求版と取得版が一致してカタログを構築できたときだけ切り替えます。失敗時は現在のカタログを保持します。状況タブに取得版と体数を表示します。配布元・BCSFEの対応が必要であり、ゲーム本体の最新版対応を保証するものではありません。
- 以後の通常編集は、確認済みの新しいカタログのゲームデータを使って不足するキャラ枠を補完します。セーブの形式バージョンや既存キャラの所持状態は変更しません。複製・保全チェックにはこの切替を適用しません。

## Beta: ログイン廃止・PayPay決済後に実行（個人利用）

- ログイン画面はありません。画面で「決済して実行」を押すと注文が作られ、PayPayで `RUN_PRICE_JPY` 円（既定100円・`0`で決済なし）の**送金リンク**を作って貼り付けます。リンクの金額・期限・未受取を確認して受け取れたら、自動で実行が始まります。
- 結果が不明・保留のときは注文を無効にし、**同じリンクを再送しません**（PayPayアプリで状態を確認してください）。支払い済みで待機枠が満杯の場合は、再送金なしで再試行できます。
- 受取側PayPayアカウントは `/admin`（`ADMIN_PASSWORD`）でログイン＋SMS認証して登録します。認証情報は `PAYPAY_ENCRYPTION_KEY`（Fernetキー。`python -c "from cryptography.fernet import Fernet;print(Fernet.generate_key().decode())"`）で暗号化。Renderの無料枠はディスクが消えるため、`RUNTIME_GITHUB_*`（非公開リポジトリ）に暗号化して保存します。
- PayPayのWeb非公式APIを使うため、仕様変更で動かなくなる可能性があります。単一インスタンス・単一ワーカー前提です。
